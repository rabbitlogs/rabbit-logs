# 9. 이미지 규칙 (전면 개정판)

> 이 절은 기존 9절을 대체한다. 개정 배경: 도식 글자가 PC에서 작고 모바일에서
> 거의 안 보이는 문제를 추적한 결과, 원인이 폰트 크기가 아니라 **캔버스 폭 고정 +
> 도식당 정보 과다**의 조합이었다. 그에 따라 크기 기준·형태 선택·정보량 규칙을
> 함께 고쳤다.

---

## 9.0 이미지를 넣을지 판단하기

- **기준**: "이 이미지가 없으면 이해가 안 되나?" — 아니면 뺀다.
- SEO 목적으로 억지로 넣은 AI 생성 이미지는 만들지 않는다.
- 남기는 건 이해를 돕는 것만: 실제 화면 캡처, 개념 정리 도식·표.
- **모든 글에 이해를 돕는 시각 자료를 최소 1개** 넣는다.

## 9.1 표시 환경 — 모든 크기 결정의 출발점

크기 판단은 **캔버스 폭이 아니라 실제 표시 폭**을 기준으로 한다. 이 순서를 뒤집으면
1200px 캔버스에 15px 글자를 넣고 "충분하다"고 착각하게 된다(실제로 그랬다).

| 환경 | 실제 표시 폭 | 800px 캔버스 기준 배율 |
|---|---|---|
| PC 본문 | 720px | 0.90배 |
| 모바일 | 약 360px | 0.45배 |

즉 캔버스의 17px 글자는 모바일에서 약 7.6px로 보인다. **모바일에서 읽히는지가
합격선**이고, PC는 자동으로 따라온다.

### 캔버스 규격

- **논리 폭 800px 기준, 실제 렌더는 2배(1600px)로 저장.** 좌표는 전부 800 기준으로
  쓰고 렌더 시점에 확대한다(레티나 대응 + 선명도).
- **폭도 내용 기준으로 역산한다.** 800은 상한이지 고정값이 아니다. 도넛+설명 목록처럼
  내용이 좁으면 폭을 줄인다. 남는 여백을 채우려고 요소를 늘리지 않는다.
  - 역산 방법: 가장 긴 텍스트를 `text_w()`로 재고, 여백·간격을 더해 필요한 폭을 구한다.
  - 실제 사례: 순환형 도식이 800px에서 우측 여백만 392px 남아 그림이 왼쪽으로 쏠렸다.
    543px로 역산해 좌우 여백을 59/61로 맞췄다.
- **높이도 같은 원칙.** 16:9 같은 비율을 강제하지 않는다. 내용 크기를 먼저 계산하고
  캔버스 높이를 역산한다.
- 렌더 후 `print(f"캔버스: {W}x{H}px")`로 실제 크기를 검증한다.
- JPG, 품질 80–92%, **200KB 이하**.
- SNS 공유용 썸네일(og:image)만 1200×630 고정 비율을 유지한다.

### 최소 폰트 (800px 캔버스 기준)

| 텍스트 위계 | 최소 크기 |
|---|---|
| 메인 타이틀 | 28 |
| 부제 | 17 |
| 강조 라벨(수치·연도) | 21 |
| 일반 라벨(항목명) | 20 |
| 설명·본문 텍스트 | 17 |

- 글자를 키울 때는 **관련 요소(아이콘 크기, 줄 간격, 패딩)도 같은 비율로** 키운다.
- 작게 보인다는 피드백을 받으면 이 표와 대조해 부족한 항목부터 올린다.
- 폰트는 **Pretendard** 고정(블로그 본문과 동일). 로드 실패 시 조용히 다른 폰트로
  대체하지 말고 그 사실을 알린다.

## 9.2 정보량 — 도식은 본문에 없는 것만 담는다

가독성 문제의 절반은 크기가 아니라 **도식이 본문을 복제**하는 데서 온다.

- 도식이 담는 것: 관계·구조·비교·변화처럼 **문장으로 쓰면 길어지는 것**
- 본문이 담는 것: 개별 항목의 세부 설명, 나열되는 조건, 예시
- **카드/항목당 텍스트는 제목 1줄 + 설명 1줄**을 기본 상한으로 한다. 불릿 3~4개를
  카드마다 넣으면 반드시 글자가 작아진다.
- 실제 사례: 파워쿼리 도식이 카드 3개 × 불릿 4개 = 12줄이었고 본문과 거의 같은
  내용이었다. 3줄로 줄이자 폰트를 21px까지 키울 공간이 생겼다.

**판단 순서**: 도식 초안을 짜고 나서, 각 텍스트가 본문에도 있는지 확인한다.
있으면 도식에서 뺀다.

## 9.3 형태 선택 — 카드형은 기본값이 아니다

**형태는 장식이 아니라 내용의 일부다.** 곡선으로 그려야 할 것을 카드로 펴면,
곡선이라는 형태가 담고 있던 정보가 사라진다.

### 선택 순서 (건너뛰지 않는다)

1. **이 도식이 말하는 관계를 한 단어로 규정한다** — 순서·대립·포함·변화·분기·균형·순환
2. 아래 표에서 그 관계에 맞는 형태를 고른다
3. **카드형을 쓰려면, 왜 다른 형태가 안 되는지 한 줄로 적을 수 있어야 한다**

카드형(2B)은 "달리 마땅한 형태가 없을 때"의 최후 선택지다. 과거 도식을 일괄
생성했을 때 49개 중 26개가 카드형으로 나와 다시 작업한 적이 있다. 익숙하다는
이유로 먼저 손이 가므로, 의식적으로 뒤로 미룬다.

| 내용의 관계 | 형태 | 쓰지 말아야 할 때 |
|---|---|---|
| 순차 진행 | 파이프라인 2H / 넘버링 2K | 순서가 아니라 병렬일 때 |
| 시간의 경과 | 타임라인 2C | 시점이 3개 이하일 때 |
| 감정·성과의 오르내림 | **곡선형 2N** | 값의 크기가 중요할 때(→ 차트) |
| 자기 참조·되돌아옴 | **순환형 2L** | 끝이 있는 흐름일 때 |
| 상위가 하위를 포함 | 계층·피라미드 2F | 포함이 아니라 나열일 때 |
| 하나가 여럿과 연결 | 방사형 2E / **좌우대칭 2J** | 중심이 없을 때 |
| 두 축으로 분류 | 매트릭스 2I | 축이 하나뿐일 때 |
| 겹치는 영역이 핵심 | 벤 다이어그램 | 겹침이 없을 때 |
| 단계마다 줄어듦 | 깔때기 | 줄어들지 않을 때 |
| 대립·트레이드오프 | 비교형 2G | 대립이 아니라 보완일 때 |
| 상태의 전후 대비 | **Before/After 2G** | 중간 과정이 중요할 때 |
| 위로 쌓이는 축적 | 스택형 2F | 순서가 없을 때 |
| 항목별 값 비교 | 차트형 2A | 수치가 없을 때 |
| 원본 데이터의 문제 | **미니 표 직접 그리기** | 데이터가 소재가 아닐 때 |
| 병렬 항목 나열 | 아이콘 그리드 | 순서가 있을 때 |

- **한 카테고리 안에서 같은 형태가 연속 3개를 넘지 않게 한다.**
- 형태가 강한 유형(벤, 저울, 피라미드, 깔때기, 순환)은 내용과 어긋나면 억지스럽다.
  "이 형태가 내용을 더 정확하게 만드는가"를 자문해 아니면 쓰지 않는다.
  - 예: 파워쿼리 정제를 깔때기로 그리면, 소계 행 제거는 줄어드는 게 맞지만
    빈 셀 채우기·형식 변환은 줄어드는 게 아니라 어긋난다.

### 카드형(2B)을 쓸 때의 표준

카드를 아예 안 쓸 수는 없으므로, 쓸 조건과 형식을 고정해둔다.

**쓸 조건**: 순서가 없는 병렬 항목 / 서로 독립된 개념 3~4개.
순서·변화·대립·순환·포함 중 하나라도 해당하면 카드가 아니다.

**형식**
- 번호와 화살표를 넣지 않는다(순서가 아니므로). 구분이 필요하면 분류 라벨
  ("오해 1", "유형 A")을 쓴다 — 번호처럼 보이되 순서를 뜻하지 않게.
- 카드 배경은 흰색, 테두리는 뉴트럴 5단계로 얇게. 강조는 **왼쪽 세로 컬러 바**.
  카드 헤더 전체나 배경을 원색으로 채우지 않는다.
- 카드 간격 최소 44px. 폭이 부족하면 간격이 아니라 카드 폭이나 항목 수를 줄인다.
- **카드당 텍스트는 제목 1~2줄 + 설명 최대 2줄.** 초과하면 폰트를 줄이지 말고
  문구를 줄인다. (실제로 초안이 3~4줄이 나와 문구를 줄여 맞춘 사례가 있다.)
- 아이콘은 선택적. 개념이 추상적이거나 항목 구분이 필요할 때만 쓰고, 순서만 있는
  도식에는 번호가 낫다.
- 카드 높이는 가장 줄 수가 많은 카드를 기준으로 역산해 모두 같게 맞춘다.

### 새로 추가된 형태

- **2J 좌우대칭** — 중앙 코어 + 양옆 2개씩. 항목이 4개일 때 카드 4열보다 낫다
  (4열은 가로로 좁아져 글자가 작아지지만, 대칭형은 항목당 폭을 확보하고 세로로 늘어난다).
- **2K 넘버링 로우** — 큰 숫자 01~04 + 옆 텍스트, 카드 대신 얇은 구분선. 테두리가
  없어 에디토리얼 방향에 가장 가깝다.
- **2L 순환형** — 도넛 조각. 조각 사이에 화살표를 넣지 않고, 링 바깥에 방향 호살표
  하나만 둔다.
- **2N 곡선형** — 3차 베지어로 실제 곡선을 그린다. 축은 얇은 선과 라벨만, 곡선 아래
  옅은 면으로 저점을 강조. 단계 포인트는 원 + 번호.

## 9.4 재료 — 형태가 달라도 재료는 고정한다

형태를 다양하게 해도 재료가 흔들리면 시리즈 통일감이 깨진다. 반대로 재료가 고정되면
형태가 달라도 "같은 블로그의 도식"으로 읽힌다.

### 팔레트 — 각 축 6단계

브랜드 원색은 그대로 두고 명도 단계를 확장한다. 원색 자체는 변경하지 않는다.

| 축 | 6단계 (진한 → 옅은) |
|---|---|
| 청록 | `#1b3a35` `#234b45` `#2c5f57` `#4e857b` `#7ba99f` `#b8d0ca` |
| 마리골드 | `#8f5c1d` `#bd7c2c` `#d99441` `#e3b071` `#eecda3` `#f7e6cd` |
| 베리 | `#7a3950` `#93465e` `#a8516e` `#c07f95` `#d6aab8` `#ecd5dd` |
| 뉴트럴 | `#25302b` `#4a534c` `#7d7768` `#a9a396` `#ded8cb` `#f0ece2` |

- 배경 `#faf8f3` 고정 (순백 아님).
- **단색 계열 운용을 우선한다.** 요소마다 다른 원색을 배정하는 대신, 한 색의 명도
  차이로 위계를 표현한다. 색 충돌과 단조로움을 동시에 해결한다.
  - 예: 오더 4단계를 청록 4단계로 → 진해질수록 확정에 가까워진다는 의미까지 전달.
- **원색은 좁은 면적에만** — 상단 띠, 테두리, 아이콘, 번호, 강조 텍스트.
- **넓은 채움 면은 옅은 톤(5~6단계)**을 쓴다. 카드 헤더 전체를 원색으로 채우지 않는다.
- 인접한 요소에 서로 다른 원색을 풀 채도로 붙이지 않는다.

### 타이틀 — 좌측 정렬 텍스트 (배너 B안)

전폭 청록 배너 대신 **좌측 짧은 컬러 룰 + 텍스트 타이틀 + 부제**를 쓴다. 모든 도식이
같은 배너를 이고 있으면 형태가 달라도 인상이 같아진다.

```
[짧은 컬러 룰 44×4px]
타이틀 (ExtraBold 27, 청록 2단계)
부제 (Medium 17, 뮤트)
```

### 아이콘 — 이모지 대신 선 아이콘

- **이모지(🏠💰)는 쓰지 않는다.** PIL에서 컬러 이모지 폰트가 깨지거나 흑백으로
  나오고, 렌더돼도 원색 광택이 브랜드 팔레트와 따로 논다.
- **선 아이콘을 브랜드 색으로 직접 그린다.** 원·사각형·선 조합이면 충분하고,
  크기·굵기·색이 전부 통제된다.
- 레스토랑 어휘로 세트를 고정해 매핑표대로 재사용한다:
  주문서(SD) · 식자재(MM) · 냄비(PP) · 접시(LE) · 영수증(CO) · 저울(QM) ·
  시계(리드타임) · 장부(FI)
- **아이콘도 "없으면 이해가 안 되나" 기준을 받는다.** 카드마다 하나씩 박으면 그
  자체가 새로운 획일성이 된다. 항목 구분이 필요할 때나 개념이 추상적일 때만 쓰고,
  순서만 있는 도식엔 번호가 낫다.

## 9.5 공통 드로잉 규칙

- **정중앙 정렬은 `textbbox()` 기반**으로 한다(`anchor="mm"`은 em box 기준이라
  실제 잉크 중심과 어긋난다). 여러 줄은 줄 단위로 개별 정렬.
- **화살표**: 도형 경계에서 gap을 두고 시작·끝낸다. 각 도형의 **실제 반지름·테두리
  좌표**를 참조한다(고정 간격 복사 금지).
  - 공용 헬퍼 하나로 통일: `gap = span×0.26`, `head = span×0.30`(최소 7px)
  - 렌더 전 `span − gap×2 − head`가 양수인지 확인. 8px 미만이면 간격을 다시 잡는다.
  - **카드 간격이 좁으면(≲30px) 비례 헬퍼를 쓰지 않고** 작은 고정값으로 직접 호출한다.
  - 역방향 화살표는 좌우 반전으로 재사용하지 말고 전용 함수를 만든다.
- **카드 사이 간격은 최소 44px.** 부족하면 간격이 아니라 카드 폭이나 항목 수를 줄인다.
- **컬러 띠는 라운드 반경을 고려해 그린다.** 직사각형을 라운드 카드 위에 겹치면
  모서리가 어긋나 틈이 생긴다.
- **피라미드는 사다리꼴 스택**으로 그린다(같은 폭 직사각형을 쌓으면 "띠"이지
  피라미드가 아니다). 폭은 라벨 텍스트 실제 폭을 재서 정한다.
- **도형만의 중심선을 캔버스 중심에 맞춘다.** 옆에 텍스트 칼럼이 붙는 구성에서
  "도형+텍스트 전체"를 중앙 정렬하면 도형이 왼쪽으로 밀려 보인다.
- **숫자·화살표는 순서에만 붙인다.** 병렬 나열에 쓰면 없는 인과관계를 만든다.
- **`level: beginner` 글의 도식엔 본문에 없는 기술 용어(테이블명·필드명·T-code)를
  노출하지 않는다.** 도식 문구는 본문 어휘 수준을 따라간다.

## 9.6 캡션·ALT·파일명

- **캡션은 이미지 밖, 마크다운 텍스트로만.** 이미지 안에 캡션 바를 그려 넣지 않는다.
  - 형식: 이미지 바로 다음 줄에 `*그림 N. 설명*` (사이에 빈 줄 없음). 표는 `*표 N. 설명*`.
  - 그림과 표는 각각 따로 번호를 매긴다.
- **ALT는 캡션과 다르게 쓴다.** 같은 문장이면 스크린리더에서 두 번 읽힌다.
  캡션은 "무엇의 그림인지", ALT는 "그림이 실제로 보여주는 값·관계"를 서술한다.
  "이미지" 같은 빈말 금지.
- **파일명**: `글슬러그-순번.jpg` (소문자+하이픈, 한글·공백·특수문자 금지).
  영문판만 `_en` 접미사. 검수용은 `_new`를 붙였다가 확정 시 뗀다.

### 영문판

- 국문 먼저 만들고 확인받은 뒤 영문 생성. **같은 스크립트의 언어 딕셔너리**
  (`T = {"ko":..., "en":...}`)에서 만들어 레이아웃 코드를 공유한다.
- **영문 라벨은 렌더 전에 폭을 검증한다.** 한글보다 길어 넘치기 쉽다. `text_w()`로
  최장 줄을 재서 카드 폭과 비교하고, **넘치면 폰트를 줄이지 말고 문구를 줄인다.**
- 영문판이 필요 없는 이미지: 텍스트 없는 사진, 라벨이 이미 영문인 그림,
  한글 SAP GUI 캡처(영문 화면은 지어내지 않는다).
- 빌드 시 `remarkEnImages`가 `_en` 존재를 확인해 자동 교체하므로, 파일만 넣으면 된다.

## 9.7 렌더 후 검증 (매번)

1. `print(f"캔버스: {W}x{H}px")` — 실제 크기 확인
2. **360px로 축소해 본다** — 합격선은 여기다
3. **여백 균형** — 좌우·상하 여백이 한쪽만 크게 남지 않았는지. 남으면 폭·높이를 역산해 줄인다
4. **영문 라벨 폭** — 카드 밖으로 넘치지 않는지
5. **용량** 200KB 이하
6. 화살표가 머리만 남지 않았는지, 라벨끼리 겹치지 않는지

## 9.8 파일·스크립트 관리

- **도식은 PIL로 만든 PNG/JPG가 표준.** 폰트가 렌더 시점에 픽셀로 고정되어 방문자
  환경과 무관하게 동일하게 보인다. SVG는 재사용이 매우 잦고 텍스트가 최소인
  예외적 경우에만 검토하고, 쓸 경우 텍스트를 아웃라인으로 변환한다.
- **스크립트는 `scripts/diagrams/`에 반드시 커밋한다.** 세션에서만 쓰고 버리면
  나중에 영문판·수정본을 만들 때 눈대중 재구성이 되어 레이아웃이 어긋난다.
- **폰트도 저장소에 커밋한다**(`scripts/diagrams/fonts/`). 세션 초기화로 `/tmp`가
  비어도 저장소 파일은 남는다. 로더는 저장소 경로를 1순위로 찾는다.
- **세션 리셋으로 `public/images/` 산출물이 사라지면 그냥 재생성한다.**
  `git checkout` 같은 복구 명령을 쓰지 않는다.
- **요청받은 슬러그만 다시 그린다.** `_runner.py`를 인자 없이 실행하면 전체가
  재생성되어 무관한 변경이 섞인다.

## 9.9 실제 SAP 화면 캡처

- 회사명·로고, 시스템 ID(우측 하단), 실제 데이터(자재 코드·거래)가 노출되지 않게 한다.
- 설정 화면 위주로 캡처하고, 회사 정보가 보이면 가리거나 크롭한다.
- 글자·선이 많은 스크린샷은 1200px 이상으로 캡처한다(축소되며 선명해진다).
  작으면 늘리지 말고 원본 그대로 둔다.

## 9.10 트러블슈팅 (겪은 문제와 해답)

- **"형태 바꾸기"와 "스타일 통일"은 다른 작업이다.** 오래된 도식을 다시 그릴 때
  원본이 이미 내용에 맞는 형태(곡선, 2×2 그리드, 아이콘 강조)를 갖고 있었다면
  그 구조는 두고 색·폰트·간격만 현재 기준에 맞춘다. "카드형으로 통일하면 관리가
  쉽겠다"는 이유로 원본 구조를 밀어버리면 형태가 담던 정보가 사라진다.
- **구조 복원 여부가 애매하면 코드를 고치기 전에 확인한다.** 재생성본과 원본의
  구조가 다를 때 어느 쪽이 기준인지는 취향이 아니라 정보 전달의 문제다.
- **"빅 키포인트" 스타일**(헤더와 불릿 사이에 큰 글자로 짧은 핵심어 하나 + 작은
  보조 설명)은 2열 비교 카드의 선택 옵션으로 템플릿화해 재사용한다.
- **타임라인은 "시작 → 번호 매긴 중간 단계 → 완료"의 3단 리듬**을 기본으로 한다.
  양 끝을 다른 색 원으로 강조하고, 상단/하단 라벨을 지그재그로 배치해 겹침을 막는다.
